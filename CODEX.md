# FitLifeTool — Codex Bootstrap

This file is a thin entrypoint. It does not duplicate project architecture,
business rules or workflow details.

1. Read `AGENTS.md` for the agent execution contract and guardrails.
2. Read `FITLIFETOOL_CONTEXT.md` for shared project orientation and the
   document router.
3. Read the current official Core planning/progress roadmap,
   `docs/project/CORE_APPLICATION_ROADMAP.md` on `develop`, and the applicable
   workflow before choosing or starting a phase. This applies to every existing
   and future FitLifeTool session; report missing current access before phase
   selection. Never create a competing roadmap or infer freshness from memory.
4. Read the relevant canonical Developer Handbook sections in
   `app/(app)/handbook/`.
5. For product-data work, read
   `docs/product-data/PRODUCT_DATA_GOVERNANCE.md`.
6. Follow Developer Handbook 5.7–5.9 and AGENTS.md for execution/security gates.
   At phase completion, check roadmap acceptance, status/evidence updates and
   the next permitted step. Include normal safe documentation maintenance in
   the same approved phase; do not start the next phase automatically.
7. Do not resolve documentation/implementation conflicts independently; stop
   and report them.
8. Follow every explicit approval gate, including permission for each push.
   Existing protected worktrees, read-only scope and release boundaries remain
   unchanged; no automatic synchronization of other sessions is implied.
